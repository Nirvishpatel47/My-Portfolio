The Problem & Context

In Gujarat, engineering diploma students preparing for the competitive DDCET (Diploma to Degree Common Entrance Test) face a challenging syllabus in mathematics, science, and engineering fundamentals. Existing entrance test portals require expensive subscriptions, constant internet connectivity, and push users toward answering high volumes of low-quality questions rather than targeting concept mastery.

I built this application as a private, 100% offline-first preparation engine designed to run entirely on the student's personal computer with zero recurring API costs, zero tracking, and zero cloud lock-in.

What I Built

The software combines an ergonomic desktop web interface with a robust local database and automated assessment routines:

  • Adaptive Topic Priority Algorithm: Evaluates past mistakes, syllabus weighting, spaced repetition urgency, and speed to suggest the most impactful topics for today's practice session.
  • Official DDCET Exam Simulation: Exact pattern matching Gujarat state entrance guidelines with 100 questions, 90-minute countdown, answer paletting, and negative marking calculations.
  • Multi-Format Question Ingestion: Bulk importers for Excel (.xlsx), CSV, JSON, and Markdown (.md) with integrated validation quarantine to isolate malformed or duplicate questions.
  • Offline Mathematical Typesetting: Bundled offline KaTeX scripts and fonts capable of rendering complex calculus integrals, matrices, and physics formulas without an internet connection.
  • Data Integrity & Safe Backups: Point-in-time SQLite database backups with one-click restore functionality.

Technical Implementation

The backend is written in Python using FastAPI and SQLite configured with write-ahead logging (WAL) for high concurrency and resilience:

Python 3.10+ FastAPI SQLite (WAL mode) OpenPyXL KaTeX Offline Keyboard Navigation
Adaptive Priority Formula: Priority = 0.35 × Weakness + 0.25 × Revision Urgency + 0.20 × Syllabus Weight + 0.10 × Neglect + 0.10 × Speed Difficulty.
Laplace smoothing is applied to prevent a single accidental wrong answer from wildly skewing a student's review queue.

What I Learned

Designing an offline-first learning system reinforced the importance of self-contained software. Eliminating external CDN dependencies, structuring relational schemas with WAL mode, and building a strict import quarantine taught me how to make software that simply works reliably without depending on a remote server.
